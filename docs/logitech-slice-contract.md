# NX-M1 implementation contract

2026-10-19. Owner approved maximum practical implementation of NX-02–04 with supervised sub-agents. Offline fixtures/builds/package verification are authorised; agents do not execute hardware helpers, inspect private configuration or post input to owner applications. Physical acceptance remains an owner checklist.

## Decisions and alternatives

15. **TOML:** select `mattt/swift-toml` exact 2.0.0, module TOML, Codable decode/encode and bounded decoder input. The reviewed release manifest contains Swift and a toml++ C wrapper, no package plugins or transitive Swift packages. Alternatives: older TOMLKit wrapper, decoder-only library plus manual writer, JSON. Native Codable and round-trip tests make the selected dependency the smaller implementation. Pin resolution and retain MIT notices. Sources: https://github.com/mattt/swift-toml and its 2.0.0 Package.swift, reviewed 2026-10-19. UI saves rewrite formatting/comments; no lossless editing promise.
16. **Model:** schema_version1, logical device profile `logitech.mx-master-3s`, required Back/Forward defaults, sparse per-bundle-identifier overrides. Missing override inherits; explicit disabled suppresses action while bindings are enabled. Defaults start disabled, not arbitrary key actions. Enabling diversion suppresses native button behaviour; UI must say so. No implicit firmware/onboard persistence.
17. **Keys:** physical macOS virtual key code with Command/Option/Control/Shift enum values. Labels use current keyboard layout, not US lookup. No arbitrary text or shell actions in first slice. One balanced down/up per fresh button press; no held repeats or delayed replay.
18. **Configuration:** config.toml under absolute XDG_CONFIG_HOME/hidhogg or home/.config/hidhogg. Atomic validated saves and last-read byte revision; detect external changes before saving. This detects ordinary edits, not a universal compare-and-swap against malicious concurrent writers. Manual reload retains last good document on failure. Whole-document draft survives navigation; reload with dirty draft requires deliberate discard or cancel. No watcher, automatic migration or silent overwrite of invalid data. Tests use temporary injected paths.
19. **Binding activation:** disabled on each launch; discovery reads only after explicit Connect. Owner confirms this is the intended MX Master 3S/Bolt candidate and no competing mouse software before enabling. Only advertised uniquely eligible Back/Forward controls can be diverted. Fresh runtime feature index, slot and baseline; no serial/unique device identifiers. Ambiguous receivers/devices fail closed. Single session owns both controls; no runtime daemon.
20. **Lifecycle:** bounded serial HID++ requests; input delivery generation-fenced and release-armed. Disabling immediately prevents action posting, then conditionally restores only states attributable to this session and separately reads restoration. Uncertain restoration stays visible and blocks rearm. Disconnect/sleep stops delivery and does not auto-reenable. Orderly quit awaits cleanup; abrupt crash recovery is not claimed.
21. **Transport:** IOKit non-seizing HID report path based on bounded LogiBridge source evidence. Forward CID/task mapping remains a candidate requiring live advertisement and owner verification. No CoreHID compatibility claim. No borrowed frozen diagnostic executable, no hardware test runs in development. Discovery timeouts are visible instead of hidden retry loops.
22. **UI:** native sidebar/Form/Picker/Button/sheets, explicit Save and Reload, native toolbar history bounded to64 deliberate routes. Store drafts above views. Connection status dot next to status text, separate from saved/permission/applied status. Custom mouse drawing only for control selection; numeric fallback key display acceptable for unmapped layout keys. No simulated connected state in production.
23. **Press admission:** a generation number alone cannot prevent a dequeued event from executing after native disconnect. A synchronous lock-protected admission gate checks the current session and a maximum 250ms event age, then completes one balanced shortcut pair before releasing the lock. Native terminal events invalidate admission immediately. Alternative: asynchronous checks before posting, which leave an interleaving window. No await or actor call occurs inside the posting closure.
24. **Save/reload transitions:** freeze draft mutation before asynchronous work begins. A save updates the submitted saved baseline; reload replaces the draft only after validation and deliberate discard confirmation where required. Missing configuration requires an intentional initial Save; load failures cannot be overwritten from the editor. Save/reload stop active bindings and require explicit reconnect/enable. Alternatives: silently overwrite a bad file or automatically re-divert hardware after saving; rejected to preserve owner control.
25. **Queued intent:** main-actor intent revisions invalidate queued Connect/Enable on Stop, sleep, quit, permission loss or recording. Controller cancellation separately guards operations already underway. Alternatives: rely on Task scheduling order or only disable posting; neither prevents a stale command starting a later session.
26. **Selective device opening:** retain explicit opening of the selected HID endpoint. Review of [Apple's IOHIDManager implementation](https://github.com/apple-oss-distributions/IOKitUser/blob/main/hid.subproj/IOHIDManager.c) found matching callbacks independent of manager-wide open; adding it would open matched devices unnecessarily. IndependentDevices scheduling isolation is a possible follow-up without a demonstrated defect; no installed-OS callback acceptance is claimed. Empty-runloop ownership regression did not reproduce a Thread cycle; finished worker references are nevertheless explicitly cleared.
27. **Owner correction to decision24:** Save/Reload/recording retain a connected idle `.ready` session, while pending activation and enabled sessions still stop and invalidate delivery. Explicit Disconnect is available independently. Alternatives: disconnect every session (the initial implementation, rejected by owner) or apply changes while diversion remains enabled (not selected). Preserve cleanup/generation fences.
28. **Reserved shortcuts:** add a manual native key/modifier chooser instead of intercepting system-wide hotkeys. App-local recording handles key equivalents only while its capture view is first responder. Existing system shortcuts can consume recording events before the app sees them; configuring a combination does not guarantee every target/system handler accepts injected events. Physical delivery remains an owner check.
29. **Accent and diagnostics:** package an AccentColor asset and NSAccentColorName for native controls; share gold for custom selection outlines. Native macOS user accent overrides remain system-controlled. Display permission blockers beside device controls. Keep recent diagnostics bounded to100; use unified logging for system-managed persistence/retention, without recording shortcut values or owner configuration. Alternative: custom rotated log files, rejected as unnecessary storage/lifecycle code for this slice.
30. **Permission affordances:** Request Permission also opens the best-effort Accessibility settings URL; a drag item supplies the running app bundle file URL. No automatic TCC edits. A successful URL-open result cannot prove the exact pane appeared; real System Settings interaction remains an owner check.
31. **Permission disagreement:** expose `AXIsProcessTrusted` and `CGPreflightPostEventAccess` as distinct results, refreshed together on app activation without prompting. Event posting continues to require the post-event preflight. Alternatives: treat Accessibility trust as sufficient or combine checks with OR; rejected because that would claim event-post permission without its actual check. A fresh process/build identity helps investigate stale processes or app entries; no TCC database inspection or reset is performed. [Apple AX trust API](https://developer.apple.com/documentation/applicationservices/1460720-axisprocesstrusted); the installed CoreGraphics header describes post-event preflight as current-process synthesizing access. The owner-reported disagreement has not yet been reproduced in the real app.
32. **Restart:** synchronously freeze new interaction, invalidate pending actions and await controller-authoritative cleanup verification; launch the same bundle through NSWorkspace with a fresh instance and running-app substitution disabled, then quit old only after launch succeeds. The owner explicitly approved brief process overlap after the old device session closes. Successor starts disconnected. Uncertain cleanup or launch failure keeps old app open; unsaved draft requires discard confirmation. Alternatives: shell relaunch helper or quit before launch; rejected to avoid helper lifecycle and losing the visible error on launch failure. [Apple fresh-instance option](https://developer.apple.com/documentation/appkit/nsworkspace/openconfiguration/createsnewapplicationinstance). Icon drag uses bundled ICNS with a native file-icon fallback and an app file-URL provider.
33. **Wheel path:** reuse advertised HID++2121 native inversion, following the separately confirmed LogiBridge v6 roundtrip. Require version1/capability0x08, valid native mode (`mode & 0xF9 == 0`, second response byte0); change only inversion0x04 and preserve resolution0x02. No event tap, synthetic scroll or global preference change. This removes a keyboard-permission dependency, not the need for production device verification. Frozen experiments remain unchanged.
34. **Wheel persistence/UI:** optional device `wheel_inverted` under schema1: nil=unmanaged,false=standard,true=reversed. Save intent only; explicit Apply while connected ready, independent of keyboard permission. Saved desired, observed device state, applying and owned restoration state are distinct. Observed state/baselines are never persisted. Unmanaged Apply releases any owned change. No auto-connect or implicit apply on launch/reload.
35. **Shared handle/lifecycle:** Apply is unavailable while keyboard bindings are enabled. Reconnect and Enable settle wheel ownership before replacing the handle; no automatic reapply. Stop/sleep/quit/restart await both cleanup paths. Alternative: retain/reapply wheel intent across keyboard Enable; deferred because it changes the existing fresh-association lifecycle and adds a hidden device write. UI must explain this session policy.
36. **Wheel ownership:** retain the original full mode across successful repeated changes, update the latest expected target before every possibly applied setter, and separately verify mode. Cleanup uses the frozen probe's strict comparison: exact original is settled; exact owned target permits restore/readback; foreign full mode is untouched and blocks rearm/restart. Alternative: restore inversion while merging externally changed resolution; rejected for this slice to avoid attributing a foreign full mode to this session. Final shutdown may release resources while retaining uncertainty; replacement never proceeds on unverified settlement. Noncooperating writers can still race read/write and must be closed by the owner.
37. **Bounded requests:** native software IDs are not reused within a handle. Repeated Apply/no-op reads must reserve enough mode-read tokens for restoration before admitting ordinary work. Exhaustion should end the session with verified cleanup when possible; no unbounded retry or token reuse is introduced.


38. **Immediate preferences (approved 2026-10-19, implemented and fixture-verified):** supersede the manual-save/enable/apply portions of decisions19,22,24,27,32,34,35. Explicit Connect opens the device and reconciles validated current preferences. Setting edits apply without waiting for disk; one-second trailing debounce writes the latest document using existing revision/conflict protection. No auto-connect at launch or after Disconnect/sleep. Reload retains the handle and reconciles only a successfully validated candidate. Alternative: throttle saves every second while editing; trailing debounce selected because owner approved one second after last edit.
39. **Shared connected session (implemented and fixture-verified):** enabling buttons retains the discovered handle and verifies fresh capabilities/baselines. Wheel preferences may change alongside bindings. Removing all shortcuts or losing keyboard permission restores buttons without closing the connection or losing the wheel change. Disabled still suppresses an action while a binding session is active; no implicit new native-passthrough action type. No configured shortcuts means no button diversion. Recording pauses action delivery and resumes from current desired preferences afterward. Alternatives: reconnect for each edit, or divert both default-disabled controls immediately; rejected as unnecessary disruption.
40. **Persistence and lifecycle (implemented and fixture-verified):** accept edits during a save, keep the submitted saved baseline separate from newer edits, serialize writes and flush before Quit/Restart. Disk failure leaves current validated preferences applied, reports unsaved state, and prevents silent exit loss. Cleanup still runs; failed flush keeps the app open. Ordinary Quit awaits the device cleanup attempt but does not trap the app open when a removed/unresponsive device cannot verify restoration; Restart remains stricter and requires verified device cleanup before launching another instance. This retains the existing quit policy while preventing disk-edit loss. External edit conflicts remain explicit and Reload requires confirmation before discarding local changes. Alternatives: discard pending edits on restart or silently overwrite external edits; rejected.
41. **Termination handshake (implemented and fixture-verified):** replace the asynchronous terminateLater/reply path with cancellation of the first quit request, asynchronous cleanup, then a separately scheduled termination request that can return terminateNow. Reserve one lifecycle transition so Quit and Restart cannot run competing cleanups. Restart verifies cleanup and pending saves before launching a disconnected successor, then permits immediate old-process termination. Existing brief process overlap remains approved; persistent duplicate processes are a defect. Prior fake-only restart tests did not exercise AppKit’s termination loop; native process-exit verification remains an owner gate because the isolated AppKit launch was rejected before its callback. [Apple termination delegate](https://developer.apple.com/documentation/appkit/nsapplicationdelegate/applicationshouldterminate(_:)).


42. **Same-handle capability budget (implemented and fixture-verified):** native software IDs are scoped to slot/feature/function, not row index or control ID. A full 8–12-row scan followed by another full scan would exceed the 15-ID allowance on the first Enable. Cache the fully validated table for the discovered connection; recheck feature index/version, count and exact Back/Forward indexed rows before diversion, plus fresh reporting baselines. The cached table supplies the same-connection uniqueness proof for other rows. Limitation: an unrelated unqueried capability row changing without connection/index/count/target-row changes is not detected. No current source establishes such metadata mutation as a supported scenario. The [Logitech-authored capability-table specification](https://lekensteyn.nl/files/logitech/x1b04_specialkeysmsebuttons.html) describes the information but does not guarantee immutability. Alternative: repeat every row and reject all larger tables; rejected because it prevents the first binding activation under the existing request-ID safety policy. No token reuse or invisible transport renewal is introduced. Synthetic fixtures must enforce the native per-signature budget and reserve reporting requests for button cleanup before diversion. Finite per-handle editing/activation capacity remains explicit; exhausting the budget requires deliberate reconnection rather than unsafe cleanup or ID reuse.
