## Ranked candidate slices

Effort assumes a focused native implementation and offline verification; physical acceptance is tracked separately.

| Rank | Slice | Value | Effort | Evidence/readiness |
|---|---|---|---|---|
| 1 | **Ordered multi-actions (recommend)** | High: broad, commonly marketed workflow and extends existing action bindings. | Medium. | Medium: official product copy claims chained/multi-step actions; local Studio 3.1.9 static investigation recovered routine/routine2/random/delay, but full schema/order/cancel semantics are incomplete. Define a native local contract rather than claim vendor serialization parity. |
| 2 | Notification icon + message and optional badge | Medium: improves the existing Hidhogg notification feature with clear current source gaps. | Low–medium. | High for the gap; low for direct Ulanzi parity. Existing render path already accepts icon and label separately, but icon suppresses text and no badge model exists. Actual display legibility still needs owner review. |
| 3 | Custom encoder display / mode 100 | High for encoder parity. | High. | Low / blocked: `Encoder.items`, `$UA1/$UA2`, and a static command-17 path are partly recovered, but model applicability and physical layout are not. Require separate evidence and scope review before any payload implementation or device write. |

**Recommendation: ordered multi-actions.** Add a bounded sequence over existing named action definitions, with order visible and a captured action/configuration snapshot. Define first-failure behavior, cancellation/deadline, and history before implementation. Keep the first contract sequential and non-nested; do not guess Ulanzi’s random/routine2 semantics, add plugin execution, or introduce new Automation permissions. Acceptance should prove: save/reload preserves sequence order; selecting/editing never runs it; one bound trigger runs children exactly once in order; interruption prevents later children; failures record partial outcome; action history identifies the sequence and child that failed. A harmless owner-triggered hardware check can follow offline/native verification.

## Deferred work and owner gates

- Multi-page physical navigation is explicitly deferred. Despite current Ulanzi product-page claims about multi-page key sets, do not make it the next implementation slice.
- Existing code’s owner gates are not missing features: check actual wide-mode/clock appearance, brightness behavior, screensaver crop placement and persistence, app icons, reconnect/sleep/wake and metric availability/calibration. No agent device writes were performed.
- Screensaver original restoration/timeout, flashing, mode-100 encoder uploads, live Now Playing, private MediaRemote, and new Automation prompts remain excluded or unapproved.
